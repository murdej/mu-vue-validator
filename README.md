# validator-vue

Vue 3 form validation helpers built on top of [yup](https://github.com/jquense/yup) — `useValidator`, plus `ErrorMessage`/`ErrorMessageList` components for displaying errors. Works well together with schemas generated by [`murdej/validator`](https://github.com/murdej/validator) (`generateYupValidator()`), but works with any plain yup `ObjectSchema`.

## Install

```bash
pnpm add validator-vue yup
```

`vue` and `yup` are regular dependencies of this package; make sure your project's own `vue`/`yup` versions are compatible (Vue 3.5+, yup 1.x).

## Usage

Given a yup schema (hand-written or generated):

```ts
// validationSchema.ts
import { object, string } from 'yup';

export const registerSchema = () => object({
  email: string().email().required(),
  nickname: string().nullable(),
});
```

Bind it to reactive form data with `useValidator`, then render fields and errors:

```vue
<script setup lang="ts">
import { reactive } from 'vue';
import { useValidator } from 'validator-vue/Composables/validator';
import ErrorMessage from 'validator-vue/Components/Forms/ErrorMessage.vue';
import { registerSchema } from './validationSchema';

const formData = reactive({ email: '', nickname: '' });
const vali = useValidator(formData, registerSchema());

async function onSubmit() {
  vali.markSubmitted();
  if (!vali.allIsValid.value) return;
  // ... send formData
}
</script>

<template>
  <form @submit.prevent="onSubmit">
    <input v-model="formData.email" v-bind="vali.for('email').inputBind" />
    <ErrorMessage :validator="vali.for('email')" />

    <input v-model="formData.nickname" v-bind="vali.for('nickname').inputBind" />
    <ErrorMessage :validator="vali.for('nickname')" />

    <button type="submit">Send</button>
  </form>
</template>
```

Notes on the example above:

- `vali.for('email')` returns (and memoizes) a child `Validator` scoped to that field path; use it for nested paths too, e.g. `vali.for('address').for('city')`.
- Errors stay hidden until a field is actually touched (its value changes) or the whole form is submitted via `markSubmitted()` — this avoids showing errors on a still-pristine form.
- `vali.for('email').inputBind` is a ready-made `v-bind` object that toggles a CSS class on the input while it has an error (and optionally one for required fields) — configurable via `useValidator(data, schema, { inputErrorClass, inputRequiredClass })`.
- `vali.allIsValid` / `vali.allErrors` aggregate errors from the whole validator tree (all `for()` children), regardless of which one you check it on.

### Listing all current errors

```vue
<script setup lang="ts">
import ErrorMessageList from 'validator-vue/Components/Forms/ErrorMessageList.vue';
</script>

<template>
  <ErrorMessageList :validator="vali" />
</template>
```

`ErrorMessageList` renders a clickable list of every current error under the given validator's path (yup + extra errors); clicking one scrolls to and briefly highlights the corresponding `ErrorMessage` element (see `toErrorMessage()`).

### Server-side / programmatic errors

Use `extraErrors` for errors that don't come from the yup schema (e.g. a server-side "email already exists" response). They behave exactly like yup errors — shown by `ErrorMessage`, counted in `allIsValid`, listed in `nestedErrorMessages` — and follow the same touched/submitted visibility rules:

```ts
const vali = useValidator<typeof formData, 'serverError'>(formData, registerSchema());

try {
  await api.register(formData);
} catch {
  vali.extraErrors.serverError = 'Email already exists';
}
```

For an error derived reactively from a child component's own state, use `bindExtraError(key, getter)` instead of assigning directly.

## API

- `useValidator(data, schema, options?)` — creates the root `Validator`.
- `Validator#for(path, index?)` — get/create a child validator for a nested field (or array item, via `index`).
- `Validator#errorMessage`, `#hasError` — current field's error state.
- `Validator#allErrors`, `#allIsValid` — whole-tree error state.
- `Validator#nestedErrorMessages`, `#nestedIsValid` — error state of the subtree rooted at this validator's path.
- `Validator#markSubmitted()` — reveal all current errors regardless of touched state.
- `Validator#reset()` — clear touched/submitted state (e.g. after reusing a validator on a form that just got reset).
- `Validator#extraErrors`, `#bindExtraError(key, getter)` — non-yup errors.
- `Validator#inputBind` — `v-bind`-able reactive class object.

## Package layout

This package ships plain `.vue` SFCs and compiled `.ts` composables, imported via subpaths (there is no single entry point):

- `validator-vue/Composables/validator`
- `validator-vue/Components/Forms/ErrorMessage.vue`
- `validator-vue/Components/Forms/ErrorMessageList.vue`
